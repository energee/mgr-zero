# Exact material-count preview (#648)

Cycle count stays one base-unit quantity per material and bin. There is no purchase-unit conversion or manual allocation editor.

One private planner owns allocation for both preview and commit. It validates the selected brewery/location/bin and each material, rejects duplicate material lines and invalid quantities, reads bin stock, and returns per-material totals plus exact signed lot adjustments. Shortages use best-by ascending, undated lots last, then receipt time and a stable ID tie-break. Overages use the newest received lot, with a stable ID tie-break. Untracked stock uses a single null-lot bucket. Zero variance has no adjustments but remains a recorded count.

The plan includes a revision derived from the selected material/bin movement identities, lot allocation metadata, and canonical requested quantities. A new registered preview query exposes safe names, quantities, base units, and this revision to Admin, Warehouse, and Brewer. Preview authenticates first and takes the same short NOWAIT locks as commit, with no request-ledger or domain writes. The locks last only for this RPC transaction; no external call occurs inside it. This briefly serializes previews across breweries, acceptable at current scale. A busy lock produces an explicit retry error distinct from a stale revision, and rolls back all acquired locks.

New record_material_count writes require the preview revision. An omitted revision can only replay an already-completed pre-migration request with its original payload hash; a new unpreviewed request raises a conflict and rolls back its claim. Commit claims its existing request ledger before checking current stock, takes NOWAIT table locks in the order materials EXCLUSIVE, material_lots SHARE, material_movements SHARE ROW EXCLUSIVE, recomputes the same plan, and rejects a changed revision with a conflict. It writes count headers, lines, and exactly the planned movements in one transaction. Replay returns the first result before checking a now-changed revision. The forward migration adds an optional trailing RPC argument to preserve six-argument legacy replay. Callers and allowlist tests change together.

The initial materials EXCLUSIVE table lock conflicts with upsert_material's SELECT FOR UPDATE table lock before that writer can hold a material row and wait on UPDATE. Ordinary reads still proceed. The lock order freezes material definitions and lot candidates before the ledger. Receiving already writes lot metadata before movements, so a count never takes the ledger lock and then waits for a receiver's lot lock. The revision includes all eligible material lots, including zero-stock lots that can win newest-lot overage allocation. Preview reads an internally consistent snapshot; commit recomputes under these locks using fresh reads. Concurrent best-by edits, new zero-stock lots, and movements must either precede the plan check or wait until count completion.

The shared CycleCountView shows each affected lot, expected and resulting quantity, and signed adjustment. Preview is an explicit action before Record count. Editing quantity or location clears the preview. A stale response requires another preview; it never silently chooses a new allocation. A transport-uncertain commit freezes its exact input and request identity for retry until the result is known. The existing shared sheet/footer owns the interaction for inventory and live adapters.

Proof covers split FEFO shortage, newest-lot overage, untracked and equal counts, missing lots, changed stock, tenant and role checks, concurrent material edits, duplicate input, rollback on stale state, and exact idempotent replay. Browser proof covers preview and commit through the shared sheet. This adds no hosted changes.
