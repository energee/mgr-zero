title: "Inventory & locations"
description: "Stock on hand, available-to-promise, movements, bins, locations and transfers between them."
---

`reverse_inventory_movement` accepts only standalone adjustments and losses. Its required note and selected movement form the retry identity; it appends an exact linked opposite with frozen package class and volume in the original bin and lot. Insufficient stock prevents removing a positive adjustment. Count/depletion and compound correction owners remain unchanged. Completed retries return the original result; changed inputs conflict. Corrections post in their own period and never rewrite filed snapshots.


`get_inventory_value` returns the brewery's current frozen-cost stock value and its uncosted units, as one total, for Admin and Sales. Cost freezes at packaging close from consumed-lot receipt costs (or last cost for untracked materials), batch knockout volume after brew-record corrections, barrels drawn, and standard packaging BOM. It has no as-of date or historical backfill.

The ledger is immutable. A movement is appended, never edited or deleted, and a
correction is a new movement in the opposite direction. That is what makes the
history admissible for excise reporting. `bbl` is computed server-side from the
SKU, so a caller must not send it.

On-hand is the sum of movements per SKU and location. Available-to-promise is
on-hand minus open allocations: the number a salesperson should be shown before
promising stock.

`list_movements` returns `{ rows, nextCursor }`, newest first by recorded timestamp and ID. Its default page has 50 rows (maximum 200). Continue with the returned `nextCursor`, preserving the timestamp exactly; omit it to read the newest page. Keep `skuId` and `movementId` unchanged when continuing a filtered history. Offset paging is no longer supported.

A stock transfer moves finished goods, materials, or empty kegs between two of
the brewery's locations, bin to bin, without an order or an invoice.
`create_stock_transfer` refuses a transfer whose source and destination
location are the same — move within one location with `move_stock_bin`
instead. `receive_stock_transfer` posts every line's paired ledger rows in one
transaction, so a transfer is never left half-received.

`create_bin` and `update_bin` reject names already used by another bin at the
same location and brewery, comparing after trimming spaces and ignoring case.
The refusal is `400 bad_request`, changes no bin or stock, and names the existing bin. Original display
spelling is preserved; a case-only rename is allowed when no other bin conflicts.
Historical case-variant bins are not rewritten, and an exact unchanged name
remains valid. An unchanged completed request replays its original result before
these checks; changing even the raw name's spaces or case with that request ID
conflicts.
